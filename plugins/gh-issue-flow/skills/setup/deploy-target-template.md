# Deploy-target doc skeleton

`setup` copies this to `.claude/workflow/deploy-targets/<name>.md` in the repo — **one file
per place code gets deployed**, not per technology — and fills it from what it probed. A
deploy target is a deploy mechanism with its own workflow, secrets handling and infra
tool: Vercel, Cloud Run, Terraform-applied infra, Fly, Kubernetes. Databases, frameworks
and auth providers are not targets; they appear inside the sections of the target that
deploys them.

Per-repo facts that do not vary by target — which bot reviews PRs, the invariants a
reviewer checks, measured traps — live in the repo's single `repo.md`
([`repo-template.md`](repo-template.md)), not here.

**The section headers are the contract**: skills read them by name, so keep every `##`
exactly as written even when a section holds only `UNVERIFIED`.

Every line under a header is one of two kinds, and says which:

- **PROBED** — a fact read from the repo, with the source path. It carries no date,
  because `git blame` dates the line.
- **UNVERIFIED — fill in** — nothing in the repo answered it. A human writes it. Skills
  treat it as an unknown and say so; they never treat it as "nothing to worry about".

Nothing is ever invented to fill a line. An honest `UNVERIFIED` is the point. Comments
and prose follow the repo's own policy, or
[`../../reference/comments-and-docs.md`](../../reference/comments-and-docs.md) when it has
none.

---

````markdown
# Deploy target: {{name}}

<!-- Generated by /gh-issue-flow:setup. Humans own this file: fill every UNVERIFIED.
     Agents propose additions in a PR handoff; they do not edit this. -->

## Identity
- Target: {{name}} — {{one line: deploy target and infra tool}}
- Detected from: {{the files and workflow lines the name came from}} — PROBED

## Deploy
<!-- Read by: issue-planner RISKS, shared/execution.md § 7, the `deploy` lens via HANDOFF. -->
- Merging {{integrationBranch}} runs: {{workflow path(s)}} — PROBED
- `paths` / `paths-ignore` on that workflow, verbatim: {{…}} — PROBED from {{workflow path}}
- Deploys with no workflow (host config present): {{vercel.json / fly.toml / …}} — or none
- Steps NOT in the CD path (infra apply, backfills, manual rolls): UNVERIFIED — fill in
- What a rollback is here: UNVERIFIED — fill in

## Secrets and env
<!-- Read by: triage § 4 disqualifiers, autopilot § 7, anyone provisioning a value. -->
- Where secrets live and the command that sets one: {{from workflows/scripts}} — PROBED, or UNVERIFIED
- The read-back that proves a value landed (byte count, type, the exact command): UNVERIFIED — fill in
- Removing or renaming an env var safely (superset first?): UNVERIFIED — fill in
- Traps measured here: UNVERIFIED

## Infra and migrations
<!-- Read by: triage § 4 gate, autopilot § 3, the `deploy` lens via HANDOFF. -->
- Migration directory and apply command: {{…}} — PROBED, or UNVERIFIED
- Infra directory and apply command; is apply in the CD path: {{…}} — PROBED, or UNVERIFIED
- Paths an unattended run must never touch: see `workflow.json` → `agentReadyForbiddenPaths` — that key owns the list; it is not copied here
- Ordering (migration ↔ image roll ↔ derived stores rebuilt): UNVERIFIED — fill in
````
